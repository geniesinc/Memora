# Quality Checks

This directory contains automated quality check scripts to ensure data integrity and consistency across the Memora project.

## Quick Start

Run all quality checks:
```bash
python quality_checks/run_all_tests.py
```

## Test Structure

### Main Test Runner
- `run_all_tests.py` - Main entry point that orchestrates all test suites

### Test Modules

#### Session Data Tests (`session_data_tests.py`)
Tests for validating session data generated by the session simulator:

1. **File Existence & Loading** - Ensures output/sessions.json exists and loads properly
2. **Empty Operation Details** - Ensures all memory operations have non-empty operation_details
3. **Session ID Sequence** - Validates session IDs are sequential starting from 1
4. **Required Session Fields** - Checks all sessions have required fields (id, type, operation, date)
5. **Session Type Validity** - Ensures session types are valid (no_memory, preference_memory, etc.)
6. **Operation Validity** - Validates operations are appropriate for their session types
7. **Operation Details Presence** - Ensures all sessions except no_memory type have operation_details key

#### Output Files Tests (`output_files_tests.py`)
Tests for validating the output files generated by the session simulator:

1. **Output Directory Exists** - Ensures the output/ directory exists
2. **Expected Output Files Exist** - Checks all expected files are present (sessions.json, memory_states_by_session.json, memory_evolution_summary.json)
3. **Output Files Valid JSON** - Validates all output files contain valid JSON
4. **Output File Sizes Reasonable** - Ensures files are not empty or suspiciously large
5. **Memory States File Structure** - Validates memory_states_by_session.json has proper structure
6. **Memory Evolution Summary Structure** - Validates memory_evolution_summary.json structure
7. **Consistent Session Counts** - Ensures session counts are consistent across all output files

#### Metadata Consistency Tests (`metadata_consistency_tests.py`)
Tests for validating consistency between metadata files and ensuring no hardcoded mismatches:

1. **Metadata Manager Loads Successfully** - Ensures all metadata files load without errors
2. **Preference Subcategories Exist** - Validates all preference categories have extracted subcategories
3. **Preference Subcategories Consistency** - Ensures subcategories match actual metadata structure (prevents bugs like "genres" in books)
4. **Personas Availability** - Validates personas are extracted from persona traits file
5. **Content Categories Extracted** - Ensures content categories are dynamically extracted
6. **Activity Categories Extracted** - Ensures activity categories are dynamically extracted  
7. **Goal Categories Extracted** - Ensures goal categories are dynamically extracted
8. **Preference Validation Works** - Tests validation logic for valid/invalid category/subcategory combinations

#### Future Test Modules
- `memory_state_tests.py` - Tests for memory state consistency
- `persona_tests.py` - Tests for persona consistency

## Adding New Tests

### Adding a Test to Existing Module
1. Add a new test method to the appropriate test class (e.g., `SessionDataTests`)
2. Follow the naming convention: `test_description_of_what_is_tested()`
3. Use `self.log_test(test_name, passed, message)` to record results
4. Call the new test method in `run_all_tests()`

### Adding a New Test Module
1. Create a new file in `quality_checks/` (e.g., `memory_state_tests.py`)
2. Create a test class with a `run_all_tests()` method
3. Import and add the new test class to `run_all_tests.py`
4. Update this README

## Test Output

Tests provide:
- ✅ **PASS** or ❌ **FAIL** status for each test
- Detailed error messages for failures
- Summary statistics (total, passed, failed, success rate)
- Sample failure examples (first 5 for readability)

## Usage Examples

### Run all tests:
```bash
python quality_checks/run_all_tests.py
```

### Run specific test module:
```bash
python quality_checks/session_data_tests.py
```

### Integration with CI/CD:
The test runner exits with code 0 for success and 1 for failures, making it suitable for automated pipelines.
